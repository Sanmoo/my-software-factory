# Status reads Docker, read-only

`msf status` touches nothing but the tracker, the workspace artifacts and a read-only Docker probe — "no IPC: the per-work artifacts are the interface." The probe — `docker ps` / `docker inspect` over the daemon's running containers — reports real worker liveness, which the registry alone cannot: it infers "in flight" from the absence of an outcome record, which both hides live workers that already wrote their outcome and mislabels genuinely running works as orphans.

The probe correlates a container to a work by its bind of the work dir, never by the configured worker image: Docker resolves that reference to whichever image it points at now, so filtering by it silently loses the workers launched before the tag moved. A container whose mounts the listing did not render is inspected too, so no absence is concluded from a column the listing failed to show. An empty running-container listing is therefore a decided zero, not an unknown — a worker is a container on the daemon the probe asks, under this workspace's works root, so that listing can hide no worker of ours. A factory resumed under a different daemon or workspace path is outside this record.

Docker is the factory's substrate (workers are containers), status still writes nothing, and it degrades to the registry-only view when Docker is unreachable. A factory heartbeat was considered and rejected: it would answer "is the loop alive while idle?", a question nobody asked, at the cost of a new artifact, a writer in the loop and staleness semantics.
