# Status reads Docker, read-only

`msf status` was defined (ticket 07 Q7) to touch nothing but the tracker and the workspace artifacts — "no IPC: the per-work artifacts are the interface." We decided status additionally makes a read-only Docker probe (`docker ps` / `docker inspect` over the host's running containers, correlating each container to a work by its bind of the work dir — never by the configured worker image, whose tag can move under a running worker — and inspecting every container whose mounts the listing did not render, so an absence is never concluded from a column the listing failed to show) to report real worker liveness, because the registry can only infer "in flight" from the absence of an outcome record — which both hides live workers that already wrote their outcome and mislabels genuinely running works as orphans. An empty running-container listing is a decided zero, not an unknown: a worker is recognised by the work it carries, never by the image tag, so the listing can hide no worker. Docker is the factory's substrate (workers are containers), status still writes nothing, and it degrades to the registry-only view when Docker is unreachable. A factory heartbeat was considered and rejected: it would answer "is the loop alive while idle?", a question nobody asked, at the cost of a new artifact, a writer in the loop and staleness semantics.
