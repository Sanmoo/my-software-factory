# Factory-owned agent resources, provisioned at image build time

Decision accepted for [issue #87](https://github.com/Sanmoo/my-software-factory/issues/87); the deterministic implementation landed with [issue #159](https://github.com/Sanmoo/my-software-factory/issues/159). `agent-resources.yaml` declares the set, `npm run build:image` provisions and records it, and the launch loads only those resources. Pi remains inside the worker container, but the worker must not require Pi, a personal Pi profile, or personal skills on the host. Declare the factory's skills and required delegation extension in this repository with explicit sources and immutable versions. Provision them during image build, not at worker startup, and fail the build on unavailable or invalid declared resources. Load only declared resources, without automatically discovering skills or packages from the target project. Model credentials are separate operational secrets, supplied explicitly through supported environment variables or an authentication file, never baked into the image or inherited through a personal-profile snapshot.

Keep Matt Pocock's upstream skills unchanged, including their supporting files and attribution. The initial set is `implement`, `tdd`, `code-review`, `pr`, and `codebase-design`, plus the required delegation extension and its operating guidance. Versioned factory prompts compose these procedures with the work context, Pi's skill-loading mechanism, local commits before review, independent Standards/Spec reviews, publication, and the existing outcome contract. Explicitly document integration exceptions rather than silently changing upstream instructions. Test seams must be unambiguously established by the approved issue/spec, although a dedicated “seams” section is not required. The agent records that interpretation before writing tests and asks for help when the spec leaves consequential alternatives; it must not invent approval or choose new seams autonomously.

This replaces personal-profile inheritance and startup provisioning with a reproducible, reviewable resource set. The trade-off is that skill updates require a reviewed declaration change and a new image; private skills, per-installation customization, and automatic target-project resource discovery are deferred. Keeping upstream skills intact avoids a maintenance fork while leaving the factory responsible for an explicit unattended-execution policy. Acceptance requires automated coverage plus an explicitly enabled real run from an empty cache on a host without Pi or personal skill directories, proving resource loading, delegation, and delivery through a PR and `desfecho.json` with separately supplied test credentials. The deterministic suite covers the provisioning contract and the real image's loading behaviour; `npm run proof:real` remains the operator-credential-gated run and is never claimed without being executed. Its GitHub-delivery half is still an outstanding operator run requiring an authorized disposable repository and credentials; it is recorded as such, not claimed.
