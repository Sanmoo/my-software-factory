# Ticket 18 — the toolchain convergence layer (focused fix on msf-v2)

**Branch:** `ticket/18-toolchains` (from `msf-v2` @ e6a18cd) — commit `82e7e0f`
**Live-proof lesson:** a worker burned its run on `go: command not found` — the container is recreated per work and nothing persisted a toolchain.

## Investigation (task 1)

- **Image (`docker/Dockerfile`):** did NOT include `mise` — no binary, no shims, nothing on PATH. RW binds at launch: profile snapshot (RO), the work dir `/msf-work` (RW), and the sessions dir → `/home/agent/.pi/agent` (RW). The snapshot itself already skips `npm` and `sessions` (`DEFAULT_SNAPSHOT_SKIP`), so an npm bind was never shadowed — it was simply absent, like the mise bind.
- **Authority:** the v1's proven `sandboxMounts` (research 01): the npm tree and the shared mise data dir bound RW so tools installed once persist across launches. (The research file was not present in the checkout — the task's mount table was used as the authority.)

## Implementation (tasks 2–3)

**`src/runtime/sandcastle.ts`**
- New exports: `TOOLCHAIN_SUBPATHS` (`mise: "toolchains/mise"`, `agentNpm: "toolchains/agent/npm"`), `MISE_CONTAINER_DIR = /home/agent/.local/share/mise`, `NPM_CONTAINER_DIR = /home/agent/.pi/agent/npm`.
- `SandcastleRuntimeOptions.workspace` (required) — the workspace root; `launch` now emits two more RW binds via `toolchainBinds()`, which `mkdir -p`s the host dirs idempotently (an existing volume is never reset). The runtime never pre-installs anything.

**`src/cli.ts`** — the real runtime is wired with `workspace: workspace.root`.

**`docker/Dockerfile`**
- `mise` installed from its **apt repo** (`mise.jdx.dev/deb`, key from `mise.jdx.dev/gpg-key.pub`) — package infrastructure only; explicitly NOT the `install.sh` route, which pulls binaries from `github.com/jdx/mise/releases` (keeps the zero-GitHub surface clean). `gnupg` added for `--dearmor` and purged with `curl` after.
- Bind mount points `/home/agent/.local/share/mise` and `/home/agent/.pi/agent/npm` created **agent-owned** in the image (bind mounts over root-owned dirs break the agent's writes).
- `ENV PATH="/home/agent/.local/share/mise/shims:${PATH}"` (docker exec inherits image ENV) + the same in `/home/agent/.profile` for login shells. Empty shims dir on first launch is harmless on PATH.

## Proof (task 5)

- **Unit (offline):** the `dockerProvider` seam captures the exact `DockerOptions` the launch hands Sandcastle — the tests assert the 5-mount table (snapshot RO; work, sessions, mise, npm RW) with workspace-derived host paths, plus an idempotence test (pre-existing files in both volumes survive two launches untouched). `npm test`: **293 pass / 0 fail** (291 baseline + 2 new); typecheck clean.
- **Image build:** `npm run build:image` succeeds; inside the image: `mise 2026.10.13`, `PATH=/home/agent/.local/share/mise/shims:...`, both mount points `agent`-owned.
- **Live convergence (two fresh containers, one host volume):**
  - launch 1: `mise install node@22` → `node -v` → v22.23.3 (installed into the bind).
  - container **recreated**; launch 2 over the same volume: `node` resolves via `/home/agent/.local/share/mise/shims/node` → v22.23.3, **no install, no download**.

## Residual risks

- The mise apt repo tracks its `stable` suite unpinned (no version pin in the Dockerfile); a future mise release could shift behavior — the v1 pinned only PI_VERSION, and this matches.
- Convergence is per-workspace (`<workspace>/toolchains/`), as specified. Works running concurrently could race on `mise install` of the same tool; mise's installs are directory-locked per tool, so worst case one waits.
- The npm bind is empty until the worker installs something into `~/.pi/agent/npm`; the snapshot deliberately skips `npm`, so nothing is shadowed.
- `msf-v2` did not advance during this task (still e6a18cd) — no merge back was needed.
- Constraints held: zero GitHub REST calls (grep-level audit: the only network surface added is mise.jdx.dev apt infra), no touching of the pkm repo, live workspace or tracker, no push, no `rm -rf` (one was blocked by the guard and replaced).
