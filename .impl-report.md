## Deviations from the prototype (and why)

1. **`tracker/fake-adapter.ts` instead of `tracker/github-adapter.ts`** — the
   ticket names the fake as the adapter born now; the GitHub adapter lands
   behind the same port in ticket 12.
2. **`cli.ts` wires the fake tracker + a placeholder runtime** (marked with
   `TODO(ticket-12)` / `TODO(ticket-13)`). This keeps `msf run --once` with an
   empty pool fully offline and exit-0, per the ticket's validation recipe;
   the placeholder runtime rejects any launch (unreachable with an empty pool).
   The `gh auth token --user` boot step (protótipo passo 2) is deferred with
   the GitHub adapter, since nothing consumes the credential before then.
3. **Added `runtime/port.ts`** (not in the 11-module tree) — the fake runtime
   needs a port to implement, mirroring the tracker pattern; the Sandcastle
   runtime of tickets 12/13 implements the same interface.
4. `pool/registry.ts`, `runtime/sandcastle.ts`, `runtime/prompt.ts` and
   `msf status`'s full view are deliberately absent — tickets 12–14.
