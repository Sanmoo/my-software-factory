## Fix 1 — Spec #7 (worst): null review body crashes the sweep

**What changed.** GitHub returns `body: null` for approval-only reviews; `readPrFeedback`
passed it through and `isAgentSpeech` crashed on `body.includes` (TypeError killing the
whole sweep). The adapter now drops review submissions with null/empty body at the mapping
(guard `isSpeechReview`, a type predicate so `body` narrows to `string`) — an approval is
not speech, and inline comments arrive through the other channel. `RestReview.body` is now
honestly `string | null`. `submitted_at: ""` — the sort-order wrinkle — stays as the honest
floor (`?? ""`); it is moot for dropped null-body entries, and a speaking review without
`submitted_at` sorts first rather than lying.

**Files.** `src/tracker/github-adapter.ts`

**Test.** `github-adapter.test.ts`: "an approval-only review (body null) is dropped — no
crash, the inline comment still counts" — reviews `[{body:null},{body:"LGTM"}]` plus one
real inline comment → only the speech-bearing submission and the inline comment remain,
so no null body can reach the derivation. Failing first (TDD), then green.

## Fix 2 — Spec #1: pool eligibility "sem PR" missing on the real adapter

**What changed.** `listCandidates` (real adapter) now enforces ticket 12's rule: after the
open-issues listing (only when it is non-empty), it reads
`repos/{repo}/pulls?state=open&per_page=100` **ONCE**, extracts linked issue numbers via
`/(?:Closes|Fixes|Resolves) #(\d+)/` from PR bodies (`linkedIssueNumbers`), and excludes
those issues. The limitation is documented in the code comment: a human PR without a
linkage keyword slips through (the honest per-issue timeline cross-ref costs one REST
call per candidate — rejected for the 60/h shared budget); only the first 100 open PRs
are read. The sim gained a `GET /repos/{repo}/pulls?state=open` listing route (state
filter, PR entries with `number`/`state`/`body`), and the shared contract suite gained a
check ("an issue linked by an OPEN PR is NOT a candidate") that both the fake and the
real-adapter-over-sim harnesses run.

**REST counts, recounted (the interesting part).** On the sim-verified cycle the derive
step's `readIssue` (isEligible early-returning on the blocked label) is REPLACED by the
open-PRs linkage listing — the seeded issue's OWN open PR (op9b, "Closes #N") now excludes
it from the pool *before* any per-candidate read: net 0. The late candidates() re-check's
listing is empty at that point (both seeded issues closed), so no linkage listing fires
there. So **`CYCLE_ADAPTER_REST_CALLS` stays 31** — breakdown comment rewritten to the
new path — and **`PLANNED_REST_CALLS` stays 57**, with the environmental note extended:
the late re-check reads the linkage listing (+1) whenever its issues listing is non-empty
(any open issue in the repo — near-certain, covered by the margin). All confirmed by the
sim's recorded-call assertion in `github-contract.test.ts`.

**Files.** `src/tracker/github-adapter.ts`, `src/tracker/github-sim.ts`,
`src/tracker/contract.ts`, `src/tracker/smoke-cycle.ts`, `src/tracker/github-smoke.ts`

**Tests.** `github-adapter.test.ts`: PR-linked issue excluded (linkage keywords Closes/
Fixes/Resolves matched, null PR body tolerated, the pulls listing read ONCE with
`state=open`); empty issues listing never reads the pulls listing; the existing dialect
test updated to route the pulls call explicitly. Contract check runs on both harnesses.

## Fix 7 — Standards #4: fragile flag string concatenation

**What changed.** Inspected pi's `buildPrintCommand` in node_modules:
`PrintCommand` is `{ command: string; stdin?: string }` — a bare command STRING, no
structured args array. So the bounded route: the flag list is single-sourced as the
exported constant `WORKER_FLAG_ARGS` (with a comment explaining why it must ride a
string), and the ONE concatenation in `runOptionsFor` applies it
(``${command.command} ${WORKER_FLAG_ARGS.join(" ")}``). No redesign.

**Files.** `src/runtime/sandcastle.ts`

**Test.** The sandcastle flag test now iterates `WORKER_FLAG_ARGS` itself — the constant
is the source, and the test proves the print command actually carries every entry.
