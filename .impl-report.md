## Notes for tickets 13/14

- **Ruler ownership:** ticket 12's collection does the minimal honest thing
  per the single ruler — PR confirmed open → stays reserved; any end without
  PR → `releaseClaim` (the 1st-fall behavior). The full ruler (fall counting
  from `desfecho.json`/absence, double fall → blocked + comment, blocked
  self-report, pre-existing PR → reserved without launch) is exactly
  ticket 13's job; its natural seam is `runOnce`'s collection block in
  `src/loop.ts` (`launchAndCollect`, lines ~85–115) — one place to extend.
- **`SweepResult` shape:** now `{ pool, launched, collected }` where
  `collected: { entry, result, prConfirmed }[]` — ticket 13 can hang the
  outcome class / transitions there. `launched` items are `SessionResult`
  (`result.request.ref` for the ref).
- **Port change note:** `claim` gained an optional `readyLabel` param
  (swap semantics). The future GitHub adapter (ticket 16) must implement the
  swap in its composite claim write — flagged in the port docstring.
- **Timing mechanism:** the fake runtime's `hold` is instance-settable and
  every e2e hold has a release path in a `finally` — mid-test failures never
  leave a worker parked; `npm test` carries a 5s per-test timeout + force-exit
  as a safety net (a hang fails fast instead of blocking the suite).
- **For ticket 14:** `runForever` still calls the wait-for-all `runOnce` on a
  fixed sleep — the event wake (end of worker vs tick) and replenishment from
  a live re-derived cache are still to come. `launchNext`'s cache drain
  already yields cleanly to "wait for the next tick" semantics.
- **Error propagation:** a worker launch that throws rejects the whole
  `runOnce` (Promise.all); every task promise is observed, so there are no
  unhandled rejections. Turning per-worker errors into the fall ruler is
  ticket 13's business.
